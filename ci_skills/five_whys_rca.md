name: 5-Whys Root Cause Analysis
description: Use when the user describes an operational breakdown, machine downtime, quality defect, scrap spike, or recurring process failure and needs root cause determination.

Procedure:
1. Define the Concrete Problem Statement:
   - What failed, where, when, and what was the quantifiable impact (e.g., 42 minutes unplanned downtime, 18 parts scrapped)?
2. Execute the 5-Whys Chain rigorously:
   - For each Why, state a verifiable factual cause (not an assumption or generic human error blame).
   - Test the backward logic using "THEREFORE": Reverse the chain from Why 5 to Why 1 using "therefore" to ensure unbroken logical causality.
3. Identify Root Cause Classification:
   - Determine whether the root cause is:
     a) Technical failure (machine, tooling, material specification).
     b) Process flaw (inadequate SOP, missing maintenance interval, uncalibrated sensor).
     c) Organizational/Systemic gap (training, supplier quality agreement, change management).
4. Formulate Mistake-Proofing Countermeasures:
   - Temporary Containment Action (stop the bleed within 24 hours).
   - Permanent Corrective Action (address the root cause).
   - Error-Proofing (Poka-Yoke) mechanism to make recurrence physically or digitally impossible.
5. Verification and Standardization:
   - Name the Owner and target completion date.
   - Specify how standard work documentation (SOP/Control Plan) will be updated.
6. Format your final response with:
   - PROBLEM STATEMENT
   - THE 5-WHYS CHAIN (Numbered 1 to 5 with forward cause and reverse "Therefore" test)
   - ROOT CAUSE VERDICT
   - COUNTERMEASURE ACTION MATRIX (Action | Type: Containment vs Permanent | Poka-Yoke Level | Target Date | Owner)
